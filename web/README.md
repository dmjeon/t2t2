# 검증 화면

`WEB` 서버의 `/usr/share/nginx/html/aadc/` 에 배포되어 `http://<WEB>/` 로 열린다.
AADC-POC.md 15절 "검증 화면 구현" 항목이다.

```
index.html          경로도 + 6개 패널
assets/style.css    라이트/다크 자동
assets/app.js       폴링 + 측정 로직 (의존성 없음, 바닐라 JS)
```

---

## 브라우저가 직접 두드리는 것은 자기 WEB 하나뿐이다

점검 VS 와 반대편 DC 는 nginx 가 `/checkvs/` `/peer/` 로 대신 물어본다.
CORS 를 피하려는 목적도 있지만, 더 중요한 이유는 **실제 서비스 경로와 같은
곳에서 본 결과**여야 의미가 있기 때문이다. 노트북에서 직접 찌른 결과는
방화벽 경로가 달라 판정에 쓸 수 없다.

## 활성 경로도

맨 위 그림은 **자기 요청을 따로 내지 않는다.** 2번 계층 카드가 이미 받아 온
응답(`/health/web`, `/api/info`, `/health/deep`, `/checkvs/`, `/peer/`)을 그대로
쓴다. 그림과 카드가 서로 다른 순간을 보게 되면 진단 화면으로서 값이 없어지기
때문이다.

**칠하는 것은 세 가지뿐이다.**

| 표시 | 뜻 | 판정 근거 |
|---|---|---|
| **파란 실선** | 지금 지나간 경로 | `web_addr`(좌/우) · `upstream_mode`(VIP 경로 / 다이렉트) · `was_dc`(교차 여부) |
| **초록 점선** | 끊겼을 때 넘어갈 수 있는 곳 | `/checkvs/` 응답 = 교차 backup 흡수 가능 · `/peer/health/deep` 200 = GSLB 이동 가능 |
| **빨간 ✕ 점선** | 설정은 됐는데 못 가는 경로 | 위 프로브 중 실패한 것 |

나머지는 배경으로 깔린다. **구성 자체가 없는 경로는 빨갛게 칠하지 않는다** —
L4 우회 중에는 backup 멤버가 아예 없으므로 "고장"이 아니라 "없음"이고, 그건
배너에 글로 나온다. 없는 것과 고장난 것이 같은 색이면 둘 다 안 보인다.

배너 세 줄이 그림 세 색과 그대로 대응한다.

```
현재  WEB-DC1  →  L4 VIP 10.3.20.100  →  WAS-APP-500 / DC-500  →  DB 10.3.31.50
대체  WAS 장애 시 WAS-APP2 로 흡수 가능 (점검 VS 응답) / DC 장애 시 DC-400 이동 가능
실패  WAS → DB writer 도달 실패 (writer_unreachable)
```

**이미 교차로 넘어가 있으면** 로컬 멤버 쪽이 빨간 ✕ 가 된다 — 설정은 살아
있는데 못 가고 있다는 뜻이고, 사람이 그 WAS 를 고쳐야 한다는 신호다.

## 쓰는 법

**평시** — 경로도가 한쪽 DC 안에서 끝나고(DCI 를 타지 않는다),
1번 배너가 초록(로컬 경유), 2번 카드 6개가 전부 초록.
4번으로 기준선(p50/p95)을 재서 적어 둔다. 이 값이 없으면 나중에 비교할 게 없다.

**D 훈련 (WAS 정지, C9/C9-a)** — 1번 배너가 노랑(교차 경유)으로 바뀌고
`/health/local` 카드만 빨강, `/health/deep` 은 초록을 유지해야 한다.
**그 조합이 설계가 의도대로 동작한다는 증거다.** 3번으로 교차 100% 를 확인하고,
4번으로 지연 증가폭을 잰다. 그 증가폭이 backup 상태 허용 시간을 정한다.

**DR 전환 1단계 직후** — 5번 쓰기가 503 으로 실패해야 한다. 실패가 정상이다.

**6번 이벤트 로그** — 자동 갱신(5초)을 켜 두고 장애를 주입하면 상태 전이 시각이
쌓인다. 전환 소요 시간을 여기서 읽는다.
