⚠ 임시 구성 — L4 우회 중

WEB 이 내부 L4 를 건너뛰고 로컬 WAS 를 직접 호출하고 있다. 서비스는 동작하지만 아래 항목은 검증된 것이 아니다. 되는 것처럼 보여도 아니다.

항목왜 검증이 안 되는가
C12 Full NAT(SNAT)L4 를 안 거치니 SNAT 자체가 일어나지 않는다
C15 backup 멤버 흡수WAS 1대가 죽으면 흡수 주체가 없다 → 곧 DC 장애
C18 L4 장비 장애 감지deep check 를 두는 유일한 단독 근거가 사라진다
5-1 경유 DC 판정via_l4 가 L4 가 아니라 WEB 주소다

내부 L4 FortiADC 가 올라오면 config.env 의 UPSTREAM_MODE=l4 로 되돌리고 30-web.sh 를 다시 돌린 뒤 위 4개를 반드시 다시 확인한다.

⚠ 임시 구성 — DB 가 SQLite

DB 서버에 아직 접근할 수 없어 WAS 로컬 파일을 쓰고 있다. 공유 DB 가 아니다 — 두 WAS 가 서로 다른 데이터를 본다. 한쪽에 쓴 값이 다른 쪽에서 보이지 않는 것이 정상이다.

항목왜 검증이 안 되는가
/health/deep 의 writer 도달 확인 로컬 파일은 언제나 도달한다. 초록불이 아무것도 증명하지 않는다
C8 DCI 단절 → DC-400 이탈 위 확인에 의존한다. DCI 가 끊겨도 DC-400 은 멀쩡해 보인다
C3~C7 DB 전환keepalived · VIP · 복제가 존재하지 않는다
semi-sync / RPO / 복제 지연SQLite 에는 복제가 없다

DB 서버가 열리면 config.env 의 DB_MODE=mariadb 로 되돌리고 20-was.sh 를 다시 돌린 뒤 위 항목을 다시 확인한다.

1. 내 요청은 어느 경로로 갔는가

L4 가 Full NAT(SNAT) 이므로 WAS 입장의 클라이언트는 nginx 가 아니라 L4 다. 그래서 via_l4 하나로 어느 DC 의 L4 를 경유했는지가 그대로 드러난다. l4_dc 와 was_dc 가 다르면 교차(backup) 경유 = degraded 상태다.

확인 중…

2. 계층별 상태

각 카드가 장애 흡수 주체 하나씩에 대응한다. DB 장애는 keepalived 가, WAS 장애는 L4 backup 이, WEB·DC 장애는 GSLB 가 흡수한다.

3. 처리 분포 C9 / C13

/api/info 를 연속 호출해 어느 WAS 가 처리했는지 집계한다. 평시에는 로컬 100% 여야 한다. 로컬 WAS 를 내리면(C9) 여기가 교차 100% 로 뒤집힌다.

#was_hostwas_dcvia_l4l4_dcms

4. 지연 측정 C2 / C2-b / C9-a

요청 1건이 쿼리 N 건을 낼 때의 실측이다. 평시 값을 기준선으로 잡아 두고, D 훈련(backup 경유) 중에 같은 값을 다시 재면 1+N 곱셈의 실제 크기가 나온다. 그 증가폭이 backup 상태 허용 시간을 정한다.

5. 쓰기 경로 DR 게이트

DR 전환 1단계만 실행한 상태에서는 여기가 503 으로 실패해야 정상이다. 쓰기는 사람이 2단계를 열어야만 열린다.

iddcwas_hostnotecreated_at

6. 이벤트 로그

상태가 바뀐 순간만 남긴다. 전환 소요 시간을 여기서 읽는다.
