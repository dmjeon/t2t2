# DR 전환 — 수동 2단 게이트

애플리케이션은 **DB VIP `10.3.31.50:3306` 에 직접 붙는다.** 중간 프록시는 두지
않는다.

```
평시   WAS → 10.3.31.50 (VIP)  →  VIP 를 잡은 노드 (.51 또는 .53)
DR시   WAS → 10.7.31.52        ←  was.env 수정 + 앱 재시작 (수동)
```

---

## 왜 프록시를 두지 않는가

**로컬 failover 에 앱측 장치가 필요 없기 때문이다.** DB-MASTER 가 죽으면
keepalived 가 VIP 를 `.53` 으로 옮기고, 앱은 같은 주소로 재연결하면 끝난다.
앱도, 앱이 올라간 호스트도 관여하지 않는다. 이 경로가 실제로 일어날 장애의
대부분이다.

남는 것은 **DR 전환뿐이고 그것은 반기 1회 훈련(C)** 이다. 조작 한 번을 위해
WAS 마다 데몬·설정파일·관리 포트·관리자 비밀번호를 상시로 이고 갈 이유가 없다.
운영 주체도 갈린다 — WAS 위의 상주 컴포넌트는 인프라가 단독으로 관리하기
어렵다.

그래서 전환 스위치를 **상주 데몬이 아니라 절차**로 둔다.

### 대신 잃는 것

| 항목 | 영향 |
|---|---|
| **1단계에 앱 재시작이 필요하다** | 재시작 창(수 초) 동안 그 WAS 는 503. **한 대씩** 돌리면 L4 가 흡수한다 |
| WAS 대수만큼 1단계를 반복한다 | 프록시가 있어도 사이드카는 WAS 마다 있으므로 반복 횟수는 같다 |
| 쿼리 다이제스트 통계가 없다 | C2(요청당 쿼리 수)는 원래 `SHOW GLOBAL STATUS` 기준이다 (AADC-POC.md 11절). 영향 없음 |

---

## 2단 게이트

```
1단계   WAS 의 AADC_DB_HOST → 10.7.31.52 + 앱 재시작     (각 WAS 에서)
2단계   DB-DR 에서 read_only=OFF 수동 해제                ← 사람이 판단
```

```bash
# 1단계 — 모든 WAS 에서, 한 대씩
./dr-failover-step1-switch-writer.sh

# 이 시점: 읽기 O, 쓰기 X (503). 이것이 정상이다.
#   /api/db/write 가 503 을 내는지 검증 화면에서 확인할 것.
#   /health/deep 도 503(writer is read_only) 이다 — 의도된 상태다.

# 2단계 — DB-DR 에서
./dr-failover-step2-enable-write.sh        # I-CONFIRM 입력 필요
```

두 단계를 분리해두면 1단계를 실수로 눌러도 쓰기가 되지 않으므로 데이터가
갈라지지 않는다. **자동화는 금지다** — 2 DC 는 쿼럼이 없어 DCI 단절과 DC 장애를
구분할 방법이 없다.

**2단계는 되돌리기 비용이 가장 높은 조작이다.** 여기를 지나면 DC-500 과 데이터가
갈라지고, 복귀하려면 역방향 복제를 다시 걸어야 한다(`dr-failback.md`).
C 훈련(반기 1회)에 **복귀 절차와 소요 시간을 반드시 포함**한다.

---

## ★ 선행 조건 — FW-27 이 적용돼 있어야 한다

**WAS → DB-DR `10.7.31.52` TCP 3306** 은 `FIREWALL-REQUEST-detail.md` §3-5 의
**FW-27** 로 신청돼 있다. 신청은 됐고, **적용 여부는 별개다.**

| FW | 내용 | 용도 |
|---|---|---|
| FW-17 | WAS → `10.3.31.50` / `.51` / `.53` | 평시 경로 |
| FW-25 | DB `10.3.31.50/.51/.53` → `10.7.31.52` | **복제** 경로 |
| **FW-27** | **WAS `10.3.21.51`, `10.7.21.52` → `10.7.31.52`** | **DR 전환 시 앱 접속** |

FW-27 은 **평시에 트래픽이 한 건도 흐르지 않는 규칙**이다. 적용이 누락돼도
오늘까지는 아무 증상이 없다가, 하필 DR 전환 순간에 드러난다. 신청서에도
"몇 달씩 미사용으로 보일 테니 정리 작업 중에 지워지지 않도록 별도 규칙으로
남겨 달라"고 적어 둔 이유가 그것이다.

그래서 1단계 스크립트가 `was.env` 를 건드리기 **전에** 도달성부터 확인하고,
실패하면 아무것도 바꾸지 않고 멈춘다. 재시작 창을 헛되이 쓰지 않는다.

> `AADC-POC.md` 12-2절 표에는 FW-27 이 빠져 있다(FW-25, FW-26 까지만).
> 신청서 쪽이 정본이며, 설계 문서 표를 맞춰 두면 좋다.

## 운용

```bash
# 이 WAS 가 지금 어디를 보고 있는가
grep -E '^AADC_DB_(HOST|PORT)=' /etc/aadc/was.env

# 실제로 닿은 writer 가 누구인가 (앱이 보고한다)
curl -s http://127.0.0.1:8000/api/db/status

# writer 신원 + read_only 를 DB 에서 직접
mysql -h 10.3.31.50 -e "SELECT @@hostname, @@server_id, @@global.read_only"
```

> 전환 이력은 `aadc.failover_log` 에 남는다. 1단계는 WAS 에서 실행되므로
> `logger -t aadc-dr`(syslog)로만 남고, 2단계가 DB 에 기록한다.
