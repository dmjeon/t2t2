## 반드시 짝으로 봐야 하는 것

**C15 와 C16.** 로컬 WAS 를 정지한 뒤

- `/health/deep` → **성공** (backup 경유) → GSLB 이동 없음
- `/health/local` → **실패** → 알람

둘 다 통과해야 "WAS 는 L4 가 흡수, DC 는 GSLB 가 흡수"라는 분리가 실제로
성립한다. 하나만 통과하면 설계가 의도와 반대로 동작하고 있는 것이다.

```bash
# WAS-APP1-500 에서
systemctl stop aadc-was
# 점프서버에서
./verify/03-health-c15-c18.sh was-down
```

## 핵심 2개

### C9-a — degraded 를 지속할 수 있는가

```bash
./verify/05-scenario-c8-c11.sh c9a 1800     # 30분
```

**이 PoC 의 핵심 산출물이다.** "WAS 1대 장애 시 backup 으로 며칠 버틸 수
있는가"에 수치로 답해야 한다. 한 번의 훈련으로 7절 제약 3개를 전부 검증한다.

스크립트가 재는 것: p50/p95/p99, 교차 비율, 에러율.
**따로 재야 하는 것**: DCI 실사용 대역(FortiGate 통계), WAS-DC2 CPU/메모리/커넥션,
알람 ①② 가 실제로 울렸는가.

### C11 — DC-400 이 100% 를 받을 수 있는가

```bash
# GSLB 가중치를 0:100 으로 바꾼 뒤
WEB1_FQDN=web2.niceci.cloud ./verify/05-scenario-c8-c11.sh c9a 1800
```

평시 1% 라고 DC-400 사양을 낮추면 DC-500 장애 순간 **100배 부하 점프**로 같이
죽는다. 이 구조에서 가장 흔한 사고 형태다. 1% 트래픽만으로는 절대 알 수 없다.

## IPL 이 검증하지 못하는 것

|  | IPL | 실제 장애 |
|---|---|---|
| 노드 상태 | 정상, 순서대로 내려감 | RST 또는 무응답 |
| 헬스체크 | 개입하지 않음 | **헬스체크가 감지해야 함** |
| 타임아웃 | 발생하지 않음 | connect timeout 누적 |

`systemctl stop` (C9) 과 `ip link set down` (C20) 은 다른 시험이다.
전자는 즉시 RST 가 돌아오고 후자는 타임아웃까지 매달린다. **둘의 차이를
정량화하는 것이 시험 목적이다.** 비계획 장애 주입은 최소 연 1회 별도 수행한다.
